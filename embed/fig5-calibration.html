Pixels before values: axis calibration

Digitization is two steps: find the marks in the image, then map pixels to values through the axis ticks and their labels. CHART-Info therefore scores tick detection (Task 4), plot-element localization in pixels (Task 6a) and calibrated values (Task 6b) as separate tasks, and a 2026 study on real charts found pixel localization consistently more accurate than the final numbers. Move one tick anchor or misread one label and watch the pixel score stay put while the value score collapses.

Figure 5. Left: the image. Blue ticks and labels are the truth; orange ticks are what the digitizer detected, with the top tick displaced by the chosen number of pixels and, optionally, its label misread. The traced curve (orange) follows the true curve (blue) up to the trace noise. Right: the same two curves after calibration, in data units. Red bars are value errors.

What to try

  • With the top tick off by 6 px, the pixel score is still above 0.9 and the tick score has only started to fall, but every value above the middle of the axis is stretched: the value recall and the NRMSE react, the pixel score does not. This is the gap between Task 6a and Task 6b.
  • Tick Misread the top label on the linear axis: 8 read as 6 compresses every value by a quarter. The trace is pixel-perfect, so the pixel score is unchanged; the largest relative error is 25% everywhere.
  • Switch to the logarithmic axis and misread 10 as 100. The calibration now assigns four decades to three decades of pixels. Values at the bottom are almost right and values at the top are ten times too large: on a log axis a label error is a multiplicative error, which is why log axes were the most frequent failure mode in PlotGround.
  • Set the tick offset to 0 and raise the trace noise. Now the two spaces agree: pixel score and value scores fall together, and the tick score stays at 1.

How it is computed

Calibration (linear): value = Lₜₒₚ · (pᵧ,ᵇₒₜ − pᵧ) ÷ (pᵧ,ᵇₒₜ − pᵧ,ₜₒₚ) with the detected top anchor pᵧ,ₜₒₚ + Δ and label Lₜₒₚ Calibration (log): log₁₀ value interpolated linearly between the detected anchors, then exponentiated Task 4 tick score (competition papers): s = 1 if d ≤ a, (b − d)/(b − a) if a < d ≤ b, 0 beyond; a = 1%, b = 2% of the image diagonal; weighted F-measure over ticks Task 6a (2022/2023 rule): per element max(0, 1 − D ÷ T), D = pixel distance, T = 5% of the smallest image dimension Task 6b recall, ε variant: Σ (1 − min(1, |v − I(P, u)| ÷ (|v| + ε))) · Interval ÷ (uₘ − u₁), ε = ground-truth range ÷ 100

Notes on this implementation

  • The x-axis is assumed perfectly calibrated; only the y-axis is perturbed. The traced curve is the true curve in pixels plus uniform jitter of the chosen amplitude.
  • CHART-Info’s task pages describe the Task 4 thresholds as set by the inter-tick spacing of each chart, whereas the ICDAR 2019 and ICPR 2020 competition papers print the 1% and 2% of the image diagonal used here. The 2019/2020 editions used T = 1% with a squared fall-off for Task 6a; the 5% linear rule is the 2022/2023 one.
  • The ε variant of the continuous metric is used so that the near-zero start of the linear curve does not dominate; without it, one pixel of trace noise at a value of 0.02 is already a total miss.
  • In the log view the right-hand axis spans 0.01 to 100 so that a misread label can be shown; the true data never exceed 10.
